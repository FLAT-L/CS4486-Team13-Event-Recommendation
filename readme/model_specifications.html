Model Architectures and Fixed Parameters

Project Story: Two Stages

Stage 1 — Modernize and simplify (01 → 02 → 05). Reproduce the historical seventh-place method, replace its model and elaborate preprocessing with XGBoost and a simpler feature pipeline, then apply focused semantic cleaning to establish a strong reference.

Stage 2 — Extract useful evidence from underused data (09 → 15). After extensive experiments with additional processing and pretrained representations, investigate whether friends’ event histories provide information beyond the existing inputs. Compare positive histories with explicit negative histories.

Model lineage: Models 09 and 15 retain Model 02’s original features. Model 05 is the strong comparison reference; its cleaning is not inherited by 09 or 15.

Fixed architectures, inputs and training settings for the eight delivered models. All folds of a model use the same configuration.

Model-specific inputs

Exact Definitions: Positive and Negative Friend Profiles

Positive friend profile (Model 09): for each friend of the target user, average the 104 event fields over events where that friend appears in event_attendees.yes. Then average these friend-level profiles equally.

Negative friend profile (Model 15): for each friend of the target user, average the same 104 event fields over events where that friend appears in event_attendees.no. Then average these friend-level profiles equally.

“Positive” and “negative” refer to friends’ recorded event responses, not to two types of friends. No recorded response does not count as a negative response.

Both profiles use the same deduplicated friend set, excluding the target user. The 104 fields are start_time, lat, lng, c_1 through c_100, and c_other. Both averaging stages operate separately for each field using available values; friends without a valid value for that field are omitted, and a field remains missing if no friend contributes. The candidate event is retained when present in a friend’s response history. The same friend can contribute to both profile types through different events; records follow the source status lists without forcing them to be mutually exclusive.

4. Five-fold training and prediction

The original split uses GroupKFold with n_splits = 5, shuffle = True and random_state = 42, grouped by user. Delivered notebooks load the preserved assignments from data/folds.csv. Each held-out user is absent from that fold’s supervised training data. Encoders are fitted only on the training rows of the corresponding fold.

OOF predictions cover every training candidate once per fold ensemble. For Models 02, 05, 09 and 15, test probabilities are averaged across all five folds: five estimators for Model 02 and ten for each other model. Candidates are sorted by descending probability with event ID as the tie-breaker. Duplicate user-event recommendations are removed. Submission columns are User and Events, with space-separated event IDs.

MAP@200

Within each user, rank candidate events by prediction. At each relevant event within the first 200 positions, calculate the fraction of preceding recommendations, including that position, that are relevant. Sum these precisions and divide by the smaller of 200 and the user’s total relevant-event count. Average the resulting AP values equally across users.

For the XGBoost pipeline, repeated user-event rows are aggregated using the maximum label and maximum prediction before ranking. Users without positives receive zero. Model 01 retains the author’s empty-positive convention of one; the fixed training dataset contains no users without positives.

7. How the estimators use the input features

XGBoost input and feature access

The training call receives a two-dimensional dense matrix: rows are candidate interactions and columns are scalar feature values. The separate target vector contains interested labels for the corresponding training rows. The exact assembly order and per-fold dimensions are documented in the data pipeline.

Each tree samples columns uniformly from the full encoded matrix using colsample_bytree: 0.8 in Models 02 and 05, and 0.9 in Models 09 and 15. There are no separate budgets for user, event, social or friend-profile features. Each one-hot column is independently eligible. Subsample selects 0.8 or 0.9 of training rows per tree, respectively.

At an internal node, histogram-based XGBoost evaluates candidate scalar thresholds using the binary-logistic objective’s gradients and Hessians. It chooses the split with the best regularized gain among eligible candidates. Thus a numerical feature might be tested against a learned threshold, while a 0/1 category indicator can separate presence from absence. A feature can appear in several nodes or trees, or remain unused.

Which branch does a missing value take?

XGBoost (02, 05, 09, 15). At a numerical split, training evaluates the gain from assigning missing observations to each child and stores a default child for that node. At prediction time, a NaN follows the stored missing child. A finite value, including zero, takes the less-than child if it is below the threshold and the other child otherwise. Different nodes can store different missing directions.

Example from Model 15. In fold 1, seed 42, tree 0, node 4 tests friend_raw_c_69. If a candidate reaches this node, its profile value determines the next step.

Categorical splits. The encoder produces finite 0/1 indicators. For example, the saved fold-1 encoder for Model 15 gives missing event cities their own event_city___missing__ indicator. A missing city sets it to 1. A city unseen during training gives zeros across the city block. Both encodings follow ordinary numerical splits.

Historical baseline (01). The forest and logistic regression first select different columns from the 35-feature vector. The forest keeps 23 columns and routes missing values using each split’s stored direction. If the split feature had no missing observations during training at that node, scikit-learn uses the child with more training samples. The logistic regression keeps 12 columns, all observed in the packaged training features. It uses these values directly and has no missing-value imputation step.

From a tree path to a recommendation score

Each candidate follows one path to one leaf in every tree. Boosting adds the learning-rate-scaled leaf contributions to the model’s initial margin, then the logistic transformation gives the positive-class probability. Models 05, 09 and 15 average probabilities from their two seeds. Within each user, candidate probabilities determine the recommendation order. The training loss is binary classification loss; it is not a pairwise ranking loss.

All original event features and the 104 friend-profile columns are available in the same matrix in Models 09 and 15. Interactions arise from successive node tests along paths. Adding a profile field does not force the tree to use it or assign it a predefined coefficient.

8. Exact Training Targets

Every delivered classifier learns train.csv.interested: 1 means interested; 0 means not labeled interested. The column not_interested is not a training target or input. Labels remain separate from the feature matrix.

Friend no responses are input evidence, not negative training labels. A candidate’s label always comes from its own interested column, regardless of its friends’ responses.

Binary logistic loss penalizes a low predicted positive probability when the label is 1, and a high probability when the label is 0. XGBoost adds trees to reduce this loss subject to its regularization settings. MAP@200 is the evaluation metric, not the differentiable training objective. At evaluation, predictions are sorted within each user to obtain a recommendation ranking.

03 · Masked event transformer. Four bidirectional blocks, width 128, four heads of width 32, pre-RMSNorm and SwiGLU width 384. Each token ties its input embedding table to its recovery head. Mask exactly three of ten tokens per event. Average field cross-entropies within each masked token, then average over masked tokens and events. Train the 1,255,936 parameters for one epoch (3,065 updates), batch 1,024, AdamW with peak learning rate 0.0003, 5% warm-up, cosine decay to 0.00003 and gradient clipping at 1. Weight decay is 0.01 on matrix parameters. Freeze the encoder for recommendation.

The downstream classifier uses 900 histogram trees, depth 4, learning rate 0.02, minimum child weight 5, L2 5, L1 0, row sampling 0.8 and tree-level column sampling 0.2. Fixed fold-specific column weights target three original columns per residual column in expectation. All 1,280 residual columns remain available. Seed 42.

04 · Supervised FT-Transformer. Three blocks, width 192, eight heads, ReGLU hidden width 256. Attention, feed-forward and residual dropout are 0.2, 0.1 and 0. Read the final CLS token through the output head. Fit one model per fold using candidate-level binary cross-entropy with logits against interested. AdamW, learning rate 0.0001, weight decay 0.00001 with the author’s parameter groups, batch 256, gradient clipping at 1, seed 42, 24 epochs per fold. Apply sigmoid to rank events per user.

06 · Dense autoencoder. Freeze 03. Encode each 1,280-value residual with a linear layer and SiLU, then decode the 64 values linearly to 1,280 with independent weights. Train 165,184 parameters for 20 epochs on the full event catalog. Minimize raw elementwise MSE. Adam, batch 4,096, seed 42, zero weight decay, cosine learning rate 0.001 to 0.00001. Fixed-weight catalog MSE was 0.00078620.

The downstream classifier uses 600 histogram trees, depth 6, learning rate 0.03, minimum child weight 5, L2 5, L1 0, row and tree-level column sampling 0.8. Average probabilities for seeds 42 and 2026. Both hybrid models fit binary logistic loss on interested with fold-local categorical encoding, and use the user-level MAP@200 protocol above.

Regenerating the neural coordinates on CPU gave 0.717494 for 03 and 0.716736 for 06 with the same saved trees. Maximum coordinate differences from the original MPS inputs were 5.96 × 10−7 and 3.94 × 10−6. Tree thresholds can turn small numerical differences into ranking changes. Reloading the original coordinates and retraining the downstream trees reproduced 0.717325 and 0.717045. Model 04 reproduced 0.692191 directly from its five checkpoints on CPU.
